# ADR-0016: Keep thin `@sveltesentio/ui/toast` wrapper WITH preset-aware sizing

- **Status**: Accepted
- **Date**: 2026-04-17
- **Amended**: 2026-11-18 (revisit check, #476); 2026-11-21 (delivery path, #643)
- **Deciders**: @lusoris (user), research agent
- **D-row**: D170 in `.workingdir/research/decisions-needed.md`

## Context

Lurkarr's `sonner/sonner.svelte:1-35` already composes `svelte-sonner` + `mode-watcher` + Lucide icons cleanly in 35 lines. The initial streamlining verdict was "downgrade to `docs/compose/toast.md`" because the composition is trivial and no cross-cutting invariant was yet committed. The user overrode that verdict by pre-committing to interface-type theming as a cross-cutting invariant: toast sizing must scale with `@sveltesentio/ui/preset-*` (desktop / 10-foot / handheld). That single invariant justifies a thin wrapper.

## Decision

Keep `@sveltesentio/ui/toast` as a **thin** wrapper (overrides initial streamlining recommendation). Ships: `svelte-sonner` re-export (ADR-0007 locked primitive) + `mode-watcher` theme binding + Lucide icons (loading/success/error/info/warning) + a preset-size hook that reads from the active `ui/preset-*` variant (`desktop` / `10-foot` / `handheld`). Pre-commits to interface-type theming direction ahead of D161/D162 locking.

## Alternatives considered

- **Downgrade to `docs/compose/toast.md`** — Lurkarr's 35-line recipe is already the proof of simplicity, but leaves preset-sizing unenforced. Every app would reimplement the size hook.
- **Bundle preset sizing into `@sveltesentio/ui` root** — spreads the concern across the package; toast-specific preset coupling is cleaner as a named sub-export.
- **Sonner upstream config only** — sonner does not expose preset-aware sizing as a first-class API.

## Consequences

**Positive**:

- Enforces interface-type theming invariant at the toast boundary (cannot be forgotten per-app).
- Lurkarr's composition pattern migrates in as the baseline.
- Preset-size hook binds to ADR-0014's shadcn-svelte / Tailwind 4 token pipeline.

**Negative / trade-offs**:

- Binds D162 + preset-\* direction before those ADRs land — intentional pre-commit, but an amendment to this ADR is required if preset shape changes.
- Wrapper is still a maintained surface (sonner × mode-watcher × Lucide × preset).

**Documentation obligations**:

- `docs/compose/toast.md` — Toaster mount, position, richColors, closeButton, preset-size hook usage.
- `@sveltesentio/ui/toast` AGENTS.md — preset-size hook contract (input: preset token; output: `toast.Options` overrides for padding/font-size/max-width).
- Cross-link to ADR-0007 (primitive lock) and the future preset-\* ADR.

## Amendment 2026-11-18: revisit check

- **Triggers checked**: Re-evaluated on `origin/main` at commit `a4b69b8` (issue #476) against two conditions of this record: the revisit condition in the Evidence section (whether `@sveltesentio/ui/preset-10foot` demands larger toasts) and the Consequences bullet that requires an amendment if the preset shape changes.
- **Verdict**: Decision stands; the thin wrapper with preset-aware sizing still earns its place, because `svelte-sonner` still lacks a first-class sizing API (`packages/ui/src/toast/preset.ts:2-6`) and remains the locked toast primitive under ADR-0007 (`docs/adr/0007-svelte-sonner-toast-primitive.md:14`). The shipped helper computes the 10-foot sizing demand: `toastPreset()` (`packages/ui/src/toast/preset.ts:65-89`) maps an `InterfaceType` or `InterfacePreset` to `position`, `width`, `gap`, `offset`, and `style`; the `10foot` preset receives `top-center` placement (`packages/ui/src/toast/preset.ts:38`) and `40rem` width (`packages/ui/src/toast/preset.ts:46`), padding, gap, and offset scale with `preset.spacingScale` (`packages/ui/src/toast/preset.ts:69-72`), and `preset.minTargetSize` is emitted as `--toast-min-target-size` (`packages/ui/src/toast/preset.ts:86`). The helper does not yet deliver that sizing to the toast; see the next bullet.
- **Delivery gap (found in review on 2026-11-21, #643)**: `svelte-sonner` 1.2.1 types `toastOptions.style` as a string (`svelte-sonner/dist/types.d.ts:269`), while `ToastPreset.style` is an object map (`packages/ui/src/toast/preset.ts:31`), so the documented `toastOptions={{ style: p.style }}` (`packages/ui/src/toast/index.ts:14`) applies no preset property; that example also omits `offset`. Passed as a string, only `--width` and `--border-radius` are read: `svelte-sonner` hard-codes toast padding and font size (`svelte-sonner/dist/Toaster.svelte:632,639`), and nothing reads `--toast-padding`, `--toast-gap`, `--font-size`, or `--toast-min-target-size`, so the WCAG 2.2 AA target-size floor for toast actions is not enforced. The reproduction in #643 mounts a real `<Toaster>` and shows both cases. Until #643 lands, the sizing invariant is stated by the helper but not met.
- **Preset shape changed (amendment cause)**: Presets ship as a single `@sveltesentio/ui/presets` sub-export (`packages/ui/package.json:98-101` exports `./presets`; `packages/ui/src/presets/index.ts:7` defines `InterfaceType` as `desktop`, `10foot`, `handheld`, and `dashboard`), landed in commit `d51d81e` (2026-06-14), rather than separate `ui/preset-*` sub-exports. `dashboard` (`packages/ui/src/presets/index.ts:59-67`) is a fourth interface type alongside the three named in the original record, and ADR-0047 (`docs/adr/0047-per-interface-presets.md:14-23`) is the preset record.
- **Shipped scope**: The runtime surface is narrower than the Decision section: `@sveltesentio/ui/toast` exports only `toastPreset` and the types `ToastPreset` and `ToastPosition` (`packages/ui/src/toast/index.ts:18-19`). It does not re-export `svelte-sonner`, bind `mode-watcher`, or bundle Lucide icons; the consuming app imports `svelte-sonner` and must pass the preset output to `<Toaster>` itself (`packages/ui/src/toast/index.ts:10-15`, `packages/ui/AGENTS.md:35`). Nothing at the toast boundary enforces this: an app can mount `svelte-sonner` without calling `toastPreset()`. The helper owns the values for the record's one cross-cutting invariant (toast sizing scales with the interface preset); applying them is an app integration requirement, and theme binding and icons remain app composition.
- **Stale guide**: `docs/compose/toast.md` still describes the fuller wrapper, with a `<Toaster>` export from `@sveltesentio/ui/toast` and sizing through `:root[data-preset]`, neither of which ships; #622 tracks rewriting it to the surface above.
- **Next revisit**: Revisit when `InterfaceType` (`packages/ui/src/presets/index.ts:7`) gains a new type, `svelte-sonner` ships preset-aware sizing upstream, the `@sveltesentio/ui/presets` export shape (`packages/ui/package.json:98-101`) changes again, or #643 changes the `ToastPreset` shape; when #643 lands, re-check that the preset sizing reaches a mounted toast.

## Amendment 2026-11-21: delivery path (#643)

- **Append-only contract (`HISS-14`)**: `ToastPreset` (`packages/ui/src/toast/preset.ts:58-75`) appends `readonly toaster: ToasterPreset` (`packages/ui/src/toast/preset.ts:21-50,74`) and `@sveltesentio/ui/toast` re-exports `ToasterPreset` (`packages/ui/src/toast/index.ts:19`), while `ToastPreset.style` (`packages/ui/src/toast/preset.ts:72,152-159`) remains unchanged in keys and values as a data map for inspection that `svelte-sonner` does not read.
- **What reaches a mounted toast**: Spreading `<Toaster {...p.toaster} />` (`packages/ui/src/toast/index.ts:14`, `packages/ui/README.md:64`, `packages/ui/AGENTS.md:35`) passes `position` (`svelte-sonner/dist/types.d.ts:78`), `offset` (`svelte-sonner/dist/types.d.ts:93-98,212`), `gap` (`svelte-sonner/dist/types.d.ts:188`, applied as `style:--gap` on the toaster `<ol>` at `svelte-sonner/dist/Toaster.svelte:417`), `style` (`svelte-sonner/dist/types.d.ts:256` `HTMLOlAttributes`, applied to every position-group `<ol>` at `svelte-sonner/dist/Toaster.svelte:432`), and `toastOptions` (`packages/ui/src/toast/preset.ts:160-170`).
- **Inline style delivery**: `p.toaster.toastOptions.style` (`packages/ui/src/toast/preset.ts:139-144,166`) formats semicolon-terminated declarations via `declarations()` (`packages/ui/src/toast/preset.ts:113-115`) for `--width` (`min(<width>, 100%)`), `--border-radius`, `padding`, and `font-size`, which `svelte-sonner` applies to each toast `<li>` (`svelte-sonner/dist/types.d.ts:269`, `svelte-sonner/dist/Toast.svelte:558`) so inline `padding` and `font-size` override the stylesheet defaults (`svelte-sonner/dist/Toaster.svelte:632,639`) and the trailing semicolon prevents `${restProps.style} ${toast.style}` (`svelte-sonner/dist/Toast.svelte:558`) from appending a space and the text `undefined` to the last declaration.
- **Toaster and toast width**: Because `toastOptions.style` reaches every toast across all position groups (`svelte-sonner/dist/Toaster.svelte:443-457`) and the toaster `<ol>` fixes `width: var(--width)` at `356px` via an unoverridable `style:--width` directive (`svelte-sonner/dist/Toaster.svelte:416,548`), `p.toaster.style` (`packages/ui/src/toast/preset.ts:31-38,138,164`) sets `min-width: min(<width>, 100% - 2 * <offset>);` on every position-group `<ol>` (`svelte-sonner/dist/Toaster.svelte:432`, `svelte-sonner/dist/types.d.ts:256`) while `p.toaster.toastOptions.style` sets `--width: min(<width>, 100%);` on each toast `<li>` (`packages/ui/src/toast/preset.ts:40-44,140`, `svelte-sonner/dist/Toaster.svelte:638`), with no `inset` or `transform` override. Widening each position-group `<ol>` to the preset width capped at the viewport minus both offsets lets each toast fill its `<ol>`, so right and left anchors (`svelte-sonner/dist/Toaster.svelte:858,862`) and centre alignment (`left: 50%; transform: translateX(-50%)` on the `<ol>` at `svelte-sonner/dist/Toaster.svelte:600`) hold for both default positions and per-toast `position` overrides; below the `600px` mobile breakpoint, the `<ol>` rule `width: 100%` (`svelte-sonner/dist/Toaster.svelte:990-996`) is never exceeded by `min-width`, and the toast `<li>` rule `width: calc(100% - var(--mobile-offset-left) * 2)` (`svelte-sonner/dist/Toaster.svelte:1002-1006`) overrides `var(--width)`, leaving `svelte-sonner`'s mobile layout unchanged. Measured in Chromium against the `svelte-sonner` 1.2.1 stylesheet (numbers in the pull request that lands this amendment): at a `1920px` viewport, `10foot` centre spans `640..1280px` in LTR and RTL; at `1024px`, `10foot` with a `bottom-right` per-toast override spans `360..1000px` and `handheld` centre spans `41..983px`; at `620px`, `10foot` spans `24..596px`; at `400px`, every preset and position spans the same edges as `svelte-sonner`'s own mobile layout (`16..384px` in LTR; `48..416px` in RTL, `16..384px` for right positions).
- **Known limit**: Presets narrower than `svelte-sonner`'s `356px` `<ol>` default (`svelte-sonner/dist/Toaster.svelte:416,548`) — specifically `dashboard` at `320px` (`packages/ui/src/toast/preset.ts:88`) — under a per-toast `*-center` position override align to the start edge of the `356px` toaster list, `18px` off the viewport centre (measured at a `1024px` viewport: `334..654px` in LTR); revisit with the `svelte-sonner` 2.x trigger below. The earlier `601–640px` `10foot` (`40rem`, `packages/ui/src/toast/preset.ts:89`) viewport overflow no longer occurs because `<ol>` `min-width` and toast `--width` clamp to the viewport minus both offsets (`620px` viewport: `24..596px`).
- **Stacking gap conversion**: `p.toaster.gap` (`packages/ui/src/toast/preset.ts:30,163`) multiplies `GAP_REM` (`0.75`, `packages/ui/src/toast/preset.ts:94`) by `preset.spacingScale` and `REM_PX` (`16`, the CSS initial root font size `1rem = 16px`, `packages/ui/src/toast/preset.ts:97`) and rounds to 4 decimal places via `roundLength()` (`packages/ui/src/toast/preset.ts:100-102`), which `scaleLength()` (`packages/ui/src/toast/preset.ts:105-110`, called for `ToastPreset.gap` at `packages/ui/src/toast/preset.ts:132`) also uses to trim trailing zeros. Expanded-stack offsets use the `gap` prop starting in `svelte-sonner` 1.2.0 (`svelte-sonner/dist/Toast.svelte:97,174` in 1.2.0), whereas `1.0.x` and `1.1.x` use a fixed `14px` constant (`svelte-sonner/dist/Toast.svelte:5,90` in 1.0.0; documented in `packages/ui/README.md:67`); the optional peer range `>=1.0.0 <2` (`packages/ui/package.json:163`) stays unchanged so this fix remains non-breaking, and raising the peer floor is tracked in #648.
- **Target-size floor on toast buttons**: `p.toaster.toastOptions.actionButtonStyle` and `p.toaster.toastOptions.cancelButtonStyle` (`packages/ui/src/toast/preset.ts:134-137,167-168`) emit `min-height: <minTargetSize>; min-width: <minTargetSize>;`, which `svelte-sonner` applies as inline styles on action and cancel buttons (`svelte-sonner/dist/types.d.ts:273,277`, `svelte-sonner/dist/Toast.svelte:654,676`) to override the hard-coded `height: 24px` rule (`svelte-sonner/dist/Toaster.svelte:728`) and enforce the WCAG 2.2 SC 2.5.8 target-size floor.
- **Verification**: Unit tests in `packages/ui/test/toast-preset.test.ts:56-125` (`builds svelte-sonner toaster props for 10foot and desktop presets` at `packages/ui/test/toast-preset.test.ts:56-85`, `keeps toaster fields consistent and semicolon-terminated across every preset` at `packages/ui/test/toast-preset.test.ts:87-99`, `handles spacingScale boundaries (0 and 0.875 dashboard)` at `packages/ui/test/toast-preset.test.ts:101-110`, and `omits unread custom properties from toaster.toastOptions.style` at `packages/ui/test/toast-preset.test.ts:112-125`) and component tests in `packages/ui/test/Toaster.svelte.test.ts:49-133` (`applies 10foot width, padding, font-size, toaster min-width, gap, offset and button target floor on a mounted toast` at `packages/ui/test/Toaster.svelte.test.ts:49-83`, `drops preset width when the object style map is passed directly to toastOptions.style` at `packages/ui/test/Toaster.svelte.test.ts:85-109`, and `keeps preset width and alignment on a per-toast position override` at `packages/ui/test/Toaster.svelte.test.ts:111-133`, stubbing `matchMedia` via `vi.stubGlobal` / `vi.unstubAllGlobals` at `packages/ui/test/Toaster.svelte.test.ts:31-47` and running with `inlineDeps: ['svelte-sonner', 'runed']` in `vitest.shared.ts:75,104-106` and `packages/ui/vitest.config.ts:8-10`) verify the mounted DOM contract.
- **Next revisit**: Revisit on `svelte-sonner` 2.x or when `svelte-sonner` exposes first-class toast width, padding, font-size, or button target-size props upstream.
